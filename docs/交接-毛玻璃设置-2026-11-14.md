## 1. 现状：管线长什么样

```
帧钩子 updater（java_natives_frame.cpp:252 附近）
  └ capture_frosted_backdrop(W, H)        ← 默认 framebuffer 里还是刚画完的世界
       整屏 glReadPixels → 1/2 → 1/4 → 横竖两趟盒式模糊 → 行翻转 → 存进 g_blur_b
begin_frame_framebuffer()
  └ dispatch(0xa) → draw_gui_frame()
       └ card_open_animation()            ← gui_cards.cpp，GUI 每帧第一件事
            gui_draw_frosted(0, 0, w, h)  ← 底板 + 模糊图 + tint
       └ 卡片、标签、文字（都走 draw_rect_rounded，材质层在 gui_layout.cpp）
  └ 世界 2D 阶段：mod_overlay_render()    ← 另一个 NanoVG context（window->dl）
       每行：nvg_image_pattern(0,0,fb_w,fb_h) + FillPaint + 半透明黑底
```

关键点：**GUI 和 HUD 用的是两个 NanoVG context**（`window->ig` / `window->dl`）。image handle 只在自己的
context 里有效，所以 `gui_frosted.cpp` 里按 context 存了两个槽（`g_slots[2]`），同一份像素缓冲喂两边。

参数位置（`src/engine/gui/gui_frosted.cpp`）：

| 常量 | 现值 | 含义 |
|---|---|---|
| `CAP_DOWNSTEPS` | 2 | 降采样档数，2 = 1/4，3 = 1/8（更糊） |
| `CAP_BLUR_RADIUS` | 5 | 是**默认值**，运行时读 `gui_frosted_blur`（本次已接） |
| `CAP_EVERY` | 3 | 每 3 帧捕获一次 |
| tint | `0.055, 0.058, 0.070, 0.08` | 背景薄雾，写死在 `gui_draw_frosted` |

等效全屏模糊 ≈ `radius × 2^downsteps`（现在是 20px）。

## 6. 任务 D：Mod Overlay 观感优化（现在「感觉一般」的正解）

现在的做法是**每行各自**：算行矩形 → 画整屏 pattern → 叠一层半透明底 → 画文字。问题四个：

| # | 问题 | 现象 |
|---|---|---|
| 1 | 每行四角都圆（`RoundedRectVarying(..., 0,0,0, round)`） | 看着像一叠独立的小胶囊，不是一个整体的列表 |
| 2 | 行与行之间没有接缝处理 | 相邻两行的模糊图是一个来源但各自裁剪，加上圆角，缝里会透出背景，边缘碎 |
| 3 | HUD 不走 `draw_rect_rounded`，所以**没有材质**（面板卡片有的顶部渐变 + 1px 描边，这里没有） | 面板和 HUD 是两种观感，割裂 |
| 4 | 亮背景时白字发糊 | 没有文字阴影 |

### 推荐改法：整块背景画一次，文字逐行叠

把「每行一块背景」改成「整个列表一块背景」：

```c
    // 1) 先量出整块的高度
    float total_h = 0.0f;
    for (i...) total_h += alpha_i * row_h_i;

    // 2) 背景只画一次：一块大圆角矩形，pattern + tint
    float top = 0.0f;
    float block_round = mod_overlay_corner_rounding;
    int fimg = frosted ? gui_frosted_image(nvg) : 0;
    if (fimg) {
        int fw = 0, fh = 0;
        gui_frosted_screen_size(&fw, &fh);
        PaintO fp = nvg_image_pattern(nvg, 0.0f, 0.0f, (float)fw, (float)fh, 0.0f, fimg, 1.0f);
        nvg_BeginPath(nvg);
        nvg_RoundedRectVarying(nvg, block_x, top, block_w, total_h, 0, 0, 0, block_round);
        nvg_FillPaint(nvg, fp);
        nvg_Fill(nvg);
    }
    nvg_FillColor(nvg, bg);
    nvg_BeginPath(nvg);
    nvg_RoundedRectVarying(nvg, block_x, top, block_w, total_h, 0, 0, 0, block_round);
    nvg_Fill(nvg);

    // 3) 材质（和面板的 draw_rect_rounded 对齐）：顶部渐变 + 1px 描边
    //    直接调 gui_layout.cpp 的 draw_rect_rounded 也行，但那会再填一次色；
    //    想精确控制就在这里用 nvg_linear_gradient + nvg_Stroke 自己画。

    // 4) 文字逐行画，各自带 alpha（淡出动画保留在文字上）
```

**这里有个取舍必须知道**：现在是**逐行淡出**（每行一个 `anim`），改成整块背景后，背景就只能用整体
alpha。建议：背景用「最后一行（最新那条）的 alpha」或者整个列表的平均 alpha，文字仍逐行淡出。
观感上没有损失 —— 一块玻璃本来就不该一行一行地淡出。

**宽度**：各行宽度不同（`e->w` 不一样的），整块背景要取**最大宽度**，否则会缺角。
`block_w = max(pad + e->w over all rows)`。

### 其他可选优化（按收益排序）

1. **文字阴影**：模块名先画一遍 `rgba(0,0,0,0.45)` 偏移 (0,1)，再画正常色。亮背景可读性立刻上来。
2. **行分隔**：行与行之间画一条 1px、`rgba(255,255,255,0.05)` 的细线，列表才有秩序感。
3. **圆角只在整块**：`block_round` 用 `mod_overlay_corner_rounding`，行内不再圆。
4. **`nvg_RoundedRectVarying` 的签名要注意**：这个仓库里它被声明成
   `(void *nvg, float x, float y, float w, float h, int a, int b, int c, float rounding)` ——
   三个 int 加一个 float，和上游 nanovg 的四个 float 不一样。**别按上游文档去传"只圆上面两个角"**，
   会静默画错。要用就先做个最小实验确认参数含义，否则老老实实用整块圆角。

## 6.5 任务 E：性能 —— 真机上已经感觉到掉帧（这条优先做）

用户在 1080p 全屏下反馈「有点掉帧」。把账算一遍就知道钱花在哪：

| 环节 | 每次捕获的代价 | 频率 | 折算 |
|---|---|---|---|
| `glReadPixels` 整屏读回 | 1920×1009×4 ≈ **7.7 MB**，而且是 GPU→CPU 同步点（要等 GPU 画完才返回） | `CAP_EVERY = 3` → 每秒约 20 次 | **≈154 MB/s 往返，每秒 20 次管线同步** |
| 降采样 1→1/2→1/4 | ≈2.0 M 像素的 2×2 平均 | 同上 | CPU |
| 两趟盒式模糊 | 480×252 × (2×5+1) × 2 ≈ 2.6 M 次采样 | 同上 | CPU |
| `nvgUpdateImage` | 484 KB 上传 | 同上 | 每帧带宽 |

还有一个放大因素：**HUD 常驻**。`mod_overlay_render` 每帧调 `gui_frosted_note_active()`，
于是只要列表在屏幕上，捕获就永不停 —— GUI 关着也在读回。

### 按性价比排序的五个改法

**E1（十分钟，掉帧立减约 2/3）** 降频。

```c
// gui_frosted.cpp:59
CAP_EVERY = 8,     // 3 → 8：捕获从每秒 20 次降到 7.5 次
```

模糊图本来就是低频图像，8 帧前的和刚拍的肉眼分不出。这是最划算的一刀。

**E2（十分钟）** 给 HUD 单独节流。

```c
extern "C" void gui_frosted_note_active(void) {
    static unsigned skip;
    if ((skip++ & 3u) != 0u) return;   // HUD 每 4 次 claim 才算一次
    g_active = 3;
}
```

叠加 E1 之后，HUD 相当于每 32 帧才刷新一次背景 —— 一串小文字条背后糊一点，没人看得出来。

**E3（收益最大，改动中等）** 别把整屏读回 CPU，先在 GPU 上缩到 1/4。

现在读 7.7 MB，其实只为了得到 480×252（484 KB）。做法：建一个 480×252 的 FBO，用
`glBlitFramebuffer` 带 `GL_LINEAR` 从默认 framebuffer 缩进去，然后 `glReadPixels` 只读 484 KB ——
**读回量降到 1/16**，同步点也没那么贵。

落地前先确认两件事：
1. `include/slinky/gl_slots.h` 里有没有 `pGlBindFramebuffer` / `pGlBlitFramebuffer` 槽。
   没有就要先在 `src/platform/gl_slots.cpp` 的加载表里加一行（格式照抄旁边的）。
2. `glBlitFramebuffer` 需要 GL 3.0。1.8.9 的上下文有可能是 2.1 compatibility profile，
   **先做一个最小实验**：在帧钩子里调一次 blit，看 GL 错误码，再决定要不要用。
   不支持的话退到 E4 或者干脆停在 E1+E2。

**E4（改动较大）** 用 PBO 把读回变成异步。

`glReadPixels` 到 PBO → 下一帧再 `glMapBuffer` 取。同步点消失，代价是延迟一帧。
需要 `ARB_pixel_buffer_object`（GL 2.1 时代就有，命中率高）。

**E5（最后手段）** HUD 不用真模糊。

给 HUD 一条兜底：半透明渐变 + 1px 描边，不做纹理。常驻开销直接归零，只留 GUI 的毛玻璃。
`gui_frosted_note_active()` 变成空函数即可，`mod_overlay.cpp` 里 `frosted` 恒为 0。

### 建议的推进顺序

```
E1 + E2  →  量一次  →  够用就停
              ↓ 还掉
            E3（先验证 glBlitFramebuffer 可用）  →  再量
              ↓ 还掉
            E4
```

### 顺手加个测量（强烈建议）

现在只有一行捕获日志，没有耗时。加计时就能从日志判断改动的效果：

```c
FN(double, time_now, ());           // 引擎里已有，java_natives_frame.cpp 用过

    double t_start = time_now();
    ...
    double ms = (time_now() - t_start) * 1000.0;
    static unsigned n;
    n++;
    if (n <= 20 || (n % 200) == 0) slinky_logf("frosted: capture %.2f ms", ms);

```

`%TEMP%\slinky.log` 里就会有一串 `frosted: capture X.XX ms`。
改动前先记一组基线（建议 3–5 ms 以下算正常，超过 8 ms 就是它了），改完再对比。

## 8. 边界：这些别动

- **`nvgImagePattern` 的句柄来源**：必须用 `nvgCreateImageRGBA` / `nvgUpdateImage`，
  不能退回 `glGenTextures` 的 GL 纹理名。原因见第 9 节第 1 条，那是这条管线唯一花了两轮才修对的地方。
- **双 context 缓存**（`g_slots[2]`）：GUI 用 `window->ig`、HUD 用 `window->dl`，handle 不通用。
- **捕获点**：必须在 `begin_frame_framebuffer()` **之前**，之后默认 framebuffer 里就没有世界了。
- **`CAP_EVERY`**：读回是 GPU 同步点，别为了"更跟手"降到 1。
- 布局 / 坐标 / 模块调度 / 事件系统 / 配置格式，一律不动。

## 9. 这条管线踩过的坑（别重犯）

| # | 坑 | 症状 | 正确做法 |
|---|---|---|---|
| 1 | `nvgImagePattern` 要 **NanoVG image handle**，不是 GL 纹理名 | 不报错、不崩、一条顶点都不发，画面毫无变化 | 用 `nvgCreateImageRGBA` / `nvgUpdateImage`；判断形态：handle 是小整数（`image 5`），GL 名是驱动给的（`tex 666`） |
| 2 | 回读缓冲按 1/4 尺寸分配，却整屏 `glReadPixels` | 1080p 往 518KB 的堆块里写 8.2MB，直接崩 | 整屏缓冲，再软件降采样 |
| 3 | `box_blur` 只跑横趟 | 拖影，不是磨砂 | 横竖各一趟 |
| 4 | 显示表面 `glReadPixels` 的 alpha 可能回 0 | 整块透明，看不见 | 降采样时把 A 强制写 255 |
| 5 | `nvg_FillColor` 夹在 `nvg_FillPaint` 与 `nvg_Fill` 之间 | 纹理被纯色覆盖，永远画不出来 | FillPaint + Fill，再另起 path 上 tint |

另外两条 UI 侧的教训：

- **高光不要画在整窗背景上**。第一版在 `gui_draw_frosted` 里加了一道顶部柔光带，结果整屏顶上一条白雾，
  像窗户自己在发光。高光属于**窗格**（卡片），不属于玻璃。
- **提亮和颗粒都不要**。试过 RGB×1.07 + 随机颗粒，副作用是"世界里的亮地面被拉成一条固定的亮带"，
  看起来像 bug。背景应当就是「世界 + 模糊 + 一层薄雾」。

## 10. 调参速查

| 想要 | 改哪 |
|---|---|
| 更糊 / 更清楚 | `CAP_DOWNSTEPS`（2 = 1/4，3 = 1/8）× `gui_frosted_blur`（滑块，1~9） |
| 背景更深 / 更透 | ClickGUI 页的 `frosted_tint`（0~40%） |
| HUD 行底更实 / 更透 | Mod Overlay 页的 `hud_frosted_tint`（0~80%） |
| 更跟手 / 更省帧 | `CAP_EVERY`（3 → 2 更跟手，→ 6 更省） |
| 两块界面色调不一致 | 两处 tint 都用 `0.055, 0.058, 0.070`，别用纯黑 |

等效全屏模糊 ≈ `gui_frosted_blur × 2^CAP_DOWNSTEPS` 像素。
