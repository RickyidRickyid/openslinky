## 一、构建与打包（不能跳步）

### 1. 编 DLL

环境变量**必须设**，否则链接阶段找不到 `libucrt.lib`：

```powershell
$msvc='C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\VC\Tools\MSVC\14.44.35207'
$sdk='C:\Program Files (x86)\Windows Kits\10'; $v='10.0.26100.0'
$env:INCLUDE="$msvc\include;$sdk\Include\$v\ucrt;$sdk\Include\$v\um;$sdk\Include\$v\shared"
$env:LIB="$msvc\lib\x64;$sdk\Lib\$v\ucrt\x64;$sdk\Lib\$v\um\x64"
$env:PATH="$msvc\bin\Hostx64\x64;$sdk\bin\$v\x64;C:\Program Files\LLVM\bin;$env:PATH"
cmake --build "D:\数据\deepseek-harness\openslinky\_build_full" --parallel 8
```

**改完源码先 touch 一下**，否则 ninja 会说 `no work to do`：

```powershell
(Get-Item $被改的文件).LastWriteTime = Get-Date
```

原因是 `Copy-Item` 会保留源文件的修改时间，ninja 按 mtime 判断，认为没动过。

### 2. 重链注入器（**最容易忘的一步**）

`Slinky.exe` 把 DLL 以 `RCDATA 200` 内嵌在自己身上，运行时解压到
`%TEMP%\slinky-<pid>\SlinkyNative.dll`。**只换 DLL 不重链 exe，游戏里永远是旧的那份。**

```powershell
$w='D:\数据\deepseek-harness\openslinky'
Copy-Item "$w\_build_full\SlinkyNative.dll" "$w\_build_inj\SlinkyNative.dll" -Force
Push-Location "$w\_build_inj"
rc.exe /nologo /fo injector_ascii.res injector_ascii.rc
link.exe /nologo /OUT:Slinky_new.exe /SUBSYSTEM:CONSOLE /MACHINE:X64 /OPT:REF /OPT:ICF `
  obj_cn\main.obj obj_cn\tui.obj obj_cn\inject_windows.obj injector_ascii.res `
  kernel32.lib user32.lib psapi.lib advapi32.lib shell32.lib
Move-Item Slinky_new.exe Slinky.exe -Force
Pop-Location
```

### 3. 四关校验（缺一不可）

同一个 SHA 必须在这**四个位置**都对上：

```powershell
foreach($p in @("$w\_build_inj\Slinky.exe",
                "$env:USERPROFILE\Desktop\Slinky\Slinky.exe",
                "$env:USERPROFILE\Desktop\Slinky-发布包\Slinky.exe")){
  & "$w\_tools\extract_rcdata200.ps1" -Exe $p    # 看 PayloadSha16
}
```

第四关是 zip 内那份。**光 SHA 一致只证明打包没错**，还要对功能基线：

```powershell
# 直接在每个字节里数某个字符串出现几次，任何一个变 0 = 内容回退
frosted / bed_esp / "gui: chinese font loaded" / BowAim / "Bed Plates" / "Target mobs"
```

### 4. 验证到底生效没有

```powershell
# 进程里加载的 DLL 与构建产物是不是同一个
Get-Process javaw -EA 0 | %{ $_.Modules | ? ModuleName -match Slinky |
  %{ (Get-FileHash $_.FileName -Algorithm SHA256).Hash.Substring(0,16) } }
```

不一致 = 游戏没重开，或注入器是旧 exe。**这一条误导过很多轮诊断。**

## 三、毛玻璃：已查明的东西，别再踩一遍

`src/engine/gui/gui_frosted.cpp`（28 KB）。原理是：把面板背后的世界像素
`glReadPixels` 出来 → 减半 → 双向 box blur → 上传成 NanoVG 纹理 → 用
`nvgImagePattern` 画在面板上。

### 六个已经踩过并修好的坑（都写在文件注释里）

1. **`nvgImagePattern` 要的是 NanoVG 的 image handle，不是 GL 纹理名。**
   传错的话 `glnvg__findTexture()` 查不到返回 NULL，`nvg__fill()` 直接
   `return 0` —— 不报错、不崩溃、一条顶点都不发。表现是「面板完全没效果」。
   正解：用 `nvgCreateImageRGBA` / `nvgUpdateImage` 让 NanoVG 自己管纹理。
   `draw_framebuffer_texture_over_screen` 传的 `renderer->fb->tex` 名字像纹理，
   实际是 `NVGLUframebuffer.image`（handle），**字段名骗人**。

2. **`box_blur()` 原来只跑横趟**，结果是拖影不是磨砂。必须横+竖两趟。

3. **`CAP_MAX` 夹错变量**，在 1440p/4K 上越界读。现在 `box_blur_h` / `box_blur_v`
   各自按行宽夹。

4. **`glReadPixels` 的 alpha 回来是 0**，直接上传会全透明，要强制 255。

5. 减半（`half_size`）是为了省带宽，480x252 的纹理铺满 1920x1009 已经够糊。

6. 面板自己的 frost 和世界的 blur 是**两个独立参数**，别让它俩互相干扰：
   只有 `frosted_blur` 影响共享的捕获。

### 当前五个可调项（GUI 里 Profils 之外的视觉设置页）

| 名称 | 默认 | 范围 | 作用 |
|---|---|---|---|
| `frosted_gui` | 开 | bool | 总开关。关掉连背景捕获一起停，零开销 |
| `frosted_tint` | 10 | 0–40 | 世界模糊层的着色 |
| `frosted_blur` | 4 | 1–9 | 共享捕获的模糊半径 |
| `Opacity` | 30 | 20–100 | 面板不透明度。100 = 实心（原版观感） |
| `Hue` | 220 | 0–360 | 面板色相，走暗色低饱和 HSV |
| `Panel frost` | 100 | 100–250 | 面板内单独放大，越大越糊（不动第二次模糊） |

### 编译期参数（`gui_frosted.cpp` L102-117 的 enum）

这些不是设置项，改完要重编。性能与观感的真正开关在这里：

| 常量 | 值 | 含义与取舍 |
|---|---|---|
| `CAP_SCALE` | 4 | 模糊图是 framebuffer 的 1/4（每轴） |
| `CAP_DOWNSTEPS` | 2 | 两轮减半到 1/4。3 = 1/8，细节更少但更快 |
| `CAP_BLUR_RADIUS` | 4 | 该尺度下的 box 半径，等效屏幕模糊 ≈ 半径 × 2^DOWNSTEPS |
| `CAP_EVERY` | 3 | **每 3 帧刷新一次**。1 = 每帧，成本翻三倍 |
| `CAP_SATURATE_NUM` | 12 | 模糊后饱和度提升，单位是 1/10 → 1.2x。1.6 会塑料化 |
| `CAP_GRAIN_AMPLITUDE` | 2 | ±2/255 dither。种子固定，图案不爬动；10 会像雪花 |
| `CAP_MAX_PIXELS` | 3840×2160 | 超过这个分辨率直接放弃背景，不做无谓的回读 |

`CAP_EVERY = 3` 是最值得先理解的：GPU 回读是同步点，每帧做会掉帧，
所以默认三帧一次、且只在有界面打开时才捕获。

编译期开关 `SLINKY_FROSTED_GUI` 还在，关掉时文件末尾（524-530）有一整套
空实现兜底，所以删函数会编译失败，要连空实现一起删。

## 四、改视觉必须知道的六件事

### 1. 3D 绘制一律用**相机相对坐标**

```c
// 错：画在几百格外，什么都看不见
GlTranslatef(worldX, worldY, worldZ);

// 对：先减去相机位置
Vec3 c = vec3_sub(centre, *camera);     // camera 在事件结构 h+8
GlTranslatef(c.x, c.y, c.z);
```

这条是 Bed Plates 当初「什么都不显示」的根因。`bed_esp.cpp` 里的写法可以直接照抄。

### 2. `gl_array_color1` = 填充，`gl_array_color2` = 线框，一个形状只能用一次

两个都调会把同一个盒子画两遍（第二遍覆盖第一遍），表现为「颜色/透明度不对」。
Bed Plates 当初就是连调两次 `color1`，alpha 0.35 被 1.0 盖掉。

### 3. 滑块必须写满六个 float

```c
SliderCfg s = { {}, label, format,
                step, scale, min, max, value, saved };
//              ↑必填  ↑必填  ↑必填 ↑必填 ↑当前值 ↑存档值
```

少写几个，剩下的就是 0，`max = 0` 会让范围读成 0，界面上拖动毫无反应。
Bed Plates 第一版只给了三个，症状是「滑块拖不动」。

### 4. 模块描述符 `0x210` 字节，事件槽位是数组下标

```c
extern "C" ModuleDescriptor xxx_module_descriptor = {
    str_name, str_desc, 2 /*Visual*/, 0 /*默认关闭*/, {0,0,0}, 0, 0, 0, {},
    {   // 一行一个槽位，下标即事件类型
        { (void *)xxx_on_tick,         0 },   //  0 tick
        {0,0}, {0,0}, {0,0}, {0,0},
        { (void *)xxx_on_toggle,       0 },   //  5 toggle
        { (void *)xxx_on_render_world, 0 },   //  6 world render（3D）
        ...
    },
    ...
};
```

**已实测有效的槽位**：`0` tick、`1` frame、`5` toggle、`6` world render、`13` 旋转覆盖。
`6` 的事件结构里 camera `Vec3` 在 `+8`。

### 5. 引擎 tick 不会替你调用别人的 tick

模块的 tick 只在自己开着的时候才被 dispatch。Bed Plates 要读 Bed ESP 的床列表，
但 Bed ESP 关着时它的 tick 根本不会跑，列表永远是空的 —— 所以
`bed_plates_tick` 里自己调了 `bed_esp_on_tick(event)`。

**做任何跨模块的视觉联动，都要检查这个。**

### 6. `aabb_expand` 的调用约定是错的，别用

引擎导出 `AABB *aabb_expand(AABB *out, AABB *b, double d)`，三个参数全是指针。
但项目里所有模块都声明成 `FN(Box, aabb_expand, (Box b, double grow))` 传值。
x64 下调用方把 box 放 RDX、引擎当成 `out` 用，引擎真正要读的 box 在 R8 是
**未初始化**的，然后往野指针写。返回值也是垃圾。

`bow_aim_assist.cpp` 和 `trajectory_predict.cpp` 已经改成手工膨胀六个数了，
照抄那种写法。**还有 5 处没改**：`aim_assist`、`trajectories`、
`imgui_widgets`（2 处）、`rotation_and_hotbar_ticks`（2 处）—— 动到它们时会崩。

## 五、提交代码

`_src_full` 本身就是 git 仓库（remote 指向 GitHub 的 `main`），直接在里面提交：

```powershell
cd "D:\数据\deepseek-harness\openslinky\_src_full"
git status --porcelain        # 看改了哪些，只有真实改动
git add -A
```

`core.autocrlf` 是 `true`、`.gitattributes` 里有 `* text=auto`，
所以工作树上的 CRLF 在提交时自动归一成 LF。**`git status` 只会显示真实改动**，
不会出现一堆「文件被重写」的假差异。

`build_check/` 之类的东西，说明 `.gitignore` 没盖住，别把它们提交进去。
## 六、视觉上还能做什么（按我看到的实际情况排）

### 优先级高

1. **`gui_frosted.cpp` 只有单向模糊，没有亮度自适应。**
   文件里有 `mean_brightness()` 但没接到着色上。世界很亮（雪地/天空）时面板
   上的白字对比度会掉，可以根据平均亮度自动微调 `Opacity` 或 tint 的暗度。

2. **颗粒与饱和度是编译期常量，没暴露成设置。** `CAP_GRAIN_AMPLITUDE = 2`
   和 `CAP_SATURATE_NUM = 12`（即 1.2x）写死在 `enum` 里，注释说明了取值理由：
   颗粒到 10 会像电视雪花，2 恰好不可见但打破平板感；饱和度 1.6 会塑料化，
   1.2 保住颜色又不发闷。想做「材质档位」就把这两个提到运行期。

3. **Bed ESP（31 KB，最大的绘制文件）里有一个 O(n²)。**
   `bed_esp_on_render_world` 每帧重建全部几何，这本身是有意的（注释写了：
   早退会让共享顶点数组状态留给上一帧）。但 L510 有个内嵌循环——
   为了把双人床的两块合并成一个 1×2 的框，**每个床都要遍历所有床**。
   100 个床就是每帧一万次比较。改成先建一张坐标哈希表（`(x,y,z)` → 索引）
   就能降到 O(n)。Bed Wars 大厅里这是帧数大头。

   `docs/BEDESP-下一步-按区块扫描.md` 写了按区块增量扫描的方案，扫描侧没做完；
   渲染侧这个 O(n²) 是另一件事，两个可以分开做。

4. **Player ESP 的 2D/3D 是两套独立绘制代码**，盒角、血量条、颜色逻辑各写一遍，
   改一处另一边不会跟。想统一风格的话这是主要障碍。

### 优先级中

5. **`name_tags.cpp`（26 KB）里字号、内边距、背景圆角都是常量**，
   没走设置。不同 GUI 缩放/分辨率下观感不一致。

6. **`indicators.cpp` 的 `GlLineWidth(1.0f)` 是写死的**，和 ESP 的 `line_width`
   设置不联动，风格不统一。

7. **`mod_overlay.cpp` 右侧模块列表**没有淡入淡出，开关模块时条目硬跳。
   按 `ToggleEvt` 加一个 0.15s 的 alpha 过渡会自然很多。

8. **`notifications.cpp` 的滑入曲线是线性的**，可以换 ease-out。

### 优先级低但值得知道

9. 所有颜色都是 `Color3`，没有 alpha 通道，所以「半透明 ESP」做不到，
   只能靠 `gl_array_color1` 的固定 alpha。

10. `localization_zh.cpp` 是硬编码的对照表，加新设置项要同时加英文 key 和中文，
    否则界面上会出现英文。

## 八、两个会浪费你半天的陷阱

### profile 会覆盖代码里的默认值

改了设置项的默认值，进游戏发现没变化 —— 先看 GUI 里实际数值。
`%USERPROFILE%\.slinky\profiles\` 里存的那份 profile 优先级更高。
这个坑在这个项目里踩了三次（`Predict` 0、`Max flight` 12、`Auto release` false）。

### 注入器不能用未知参数试跑

现在的中文版对未知选项会报错退出（安全），但 11-15 的旧版本不认 `--list`，
会把参数丢掉**直接自动注入**。测之前先读 `injector/main.cpp` 确认分支存在。
