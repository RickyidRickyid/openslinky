# 毛玻璃 GUI 接入说明（2026-11-14 第二版）

> 目标：GUI 打开时，面板背后是当前世界画面 1/4 降采样 + 盒式模糊后再拉伸回去的结果，转视角跟着变，
> 顶部一道细高光。**不是半透明色块。**

## 0. 一句话

上一版「捕获成功、绘制不显示」不是 alpha、不是捕获、不是 FBO，是 **`nvgImagePattern` 传了 GL 纹理名，
而它要的是 NanoVG 的 image handle**——找不到就静默跳过整个填充。这一版把纹理改由 NanoVG 自己创建/更新，
另外补了纵向模糊、alpha、以及 1/4 尺寸上限的越界读。**默认关**（`SLINKY_FROSTED_GUI 0`），改一行开启。

## 2. 上一版为什么画不出来（真因）

`nvgImagePattern` 返回的 `NVGpaint` 里存的是 **image handle**。绘制时
`glnvg__findTexture(gl, paint->image)` 在上下文自己的纹理表里按 id 线性找，找不到返回 `NULL`，
`nvg__fill()` 直接 `return 0`：**不报错、不崩、一条顶点都不发**。

上一版用 `glGenTextures` 上传，然后把 GL 纹理名（日志里的 `id 519`）当 handle 传进 `nvgImagePattern`。
GL 名字是驱动分配的（几百上千），image handle 是 NanoVG 自己从 1 开始编号的，两者永远对不上，于是填充被静默跳过。

对照证据（同一个仓库里两条已验证可用的路径）：

- `gui_layout.cpp:415 draw_framebuffer_texture_over_screen()` 传 `renderer->fb->tex`；
- `gui_layout.cpp:235 draw_texture()` 传 `GImg->tex`（偏移 0x48）。

`FBuf { char pad[0x14]; int tex; }` 的 `+0x14` 正好是 `NVGLUframebuffer.image`
（`ctx` 8 + `fbo` 4 + `rbo` 4 + `texture` 4 = 0x14），也就是说它叫 tex、实际是 **image handle**。
`draw_texture` 的 `GImg->tex` 同理（那是列表里存好的 handle）。这两条能画，是因为它们传的本来就是 handle。

另外两个「即使 handle 对了也会出错」的问题：

1. **alpha**：`glReadPixels` 在无 alpha 通道的显示表面上可能回 0，`FillPaint` 画出来整块透明。
   现在降采样时直接把 A 写成 255。
2. **模糊只有横向**：上一版 `box_blur()` 只跑了横趟（拖影，不是磨砂）。现在横、竖各一趟。

还有一个越界隐患：`CAP_MAX_W/H = 480/320` 是在降采样**之后**去夹 `sw/sh` 变量，没有夹缓冲区——
1440p（3600/4=900）和 4K 下 `box_blur` 会按 480 的宽度去读 900 宽的行，图像错位、越界读。
这一版按 `fb/4` 走，只保留 4K 总像素保护（超过就整块关掉，不画）。

## 3. 现在的绘制顺序

```
帧钩子（updateDisplay）                       ← 默认 framebuffer 里是刚渲染完的世界
  └ capture_frosted_backdrop(W, H)            ← 整屏 glReadPixels → 1/2 → 1/4 → 横竖模糊 → 行翻转
begin_frame_framebuffer()                     ← 绑定 GUI 的 FBO 并清空（世界到此为止）
  └ dispatch(0xa) → draw_gui_frame()
       └ card_open_animation()                ← GUI 每帧第一件事
            ├ 1. 不透明底板（0.055 灰）
            ├ 2. nvgImagePattern(handle) + FillPaint + Fill   ← 模糊世界铺满，stretch 回整窗
            ├ 3. 另起 path 上 tint（Alpha 0.45）
            └ 4. 顶部 1.5px 高光
  └ 卡片、标签、文字……
clear_frame()                                 ← 结束 GUI 的 nvg 帧，绑回默认 framebuffer
begin_frame() → draw_framebuffer_texture_over_screen()   ← 把 GUI FBO 贴回屏幕
```

捕获只在面板真的在画的时候跑：除了调用点的 `[0x14]` 判断，`gui_draw_frosted` 每帧还会把
`g_active` 置 3，连续 3 帧没画面板就自动停掉 `glReadPixels`（防止那个标志恒为真时白读）。

## 4. 怎么验证的（这台机器上做到的）

这台机器**没有** MSVC / LLVM / CMake，跑不了游戏，所以分两层验证：

**① 编译（两种配置都过）**

用 zig 0.17.1 自带的 clang，`-target x86_64-windows-gnu`（只做语法/类型检查，不是最终 ABI）：

```
src/engine/gui/gui_frosted.cpp
src/engine/gui/gui_cards.cpp
src/engine/base/java_natives_frame.cpp
```

`SLINKY_FROSTED_GUI = 0` 和 `= 1` 两种都编过（`-c` 出 .o，EXIT=0）。注意这只证明能编过，
真实构建仍以 `build.ps1`（clang-cl + Windows SDK）为准。

**② 像素管线（真代码，合成画面）**

`_check/frosted_harness.cpp` 把 `gui_frosted.cpp` 原样编进去，桩掉 GL / NanoVG / libc，
用一张 320×200 的合成画面（下半红、上半绿、屏幕左上角 40×40 白块，**alpha 故意给 0**）走真实
`capture_frosted_backdrop` → `gui_draw_frosted`，在 `nvgCreateImageRGBA` 处截下真正要上传的像素：

```
frosted: 320x200 -> 80x50, blur r=3, mean=71.3
frosted: image 7 created (80x50)
upload 80x50
top row rgb=(0,200)  bottom row rgb=(200,0)      ← 翻转正确：屏幕上方=绿
bleed below=72, right=72, away=0                 ← 横竖都有模糊渗色，远处仍是纯绿
alpha 全部 255                                    ← 不再透明
RESULT ok
```

输出图：`_check/frosted_result.png`（白块在左上、四周有模糊晕开、绿红交界有过渡带）。

**③ 没验到的（必须在真机做）**

- 游戏里到底出不出现、位置对不对（FBO 绑定、composite、坐标系只有真机能证）；
- 帧率代价（整屏 `glReadPixels` 是同步点，按 `CAP_EVERY=3` 预估 1–3 fps）；
- 与其它 GUI 元素（弹窗、toast、拖拽）叠加时的观感。

## 5. 真机构建 & 验收步骤

1. 打开开关：`include/slinky/gui_frosted.h` 第 9 行 `#define SLINKY_FROSTED_GUI 0` → `1`。
2. `.\build.ps1`（client + injector 一起）。**注入器必须重链**：`Slinky.exe` 把 DLL 嵌在自己身上，
   只编 DLL 不重链 exe，游戏里永远是旧的那份。
3. 完全关掉 javaw 再重开，比对 SHA：
   ```powershell
   Get-Process javaw -EA 0 | %{ $_.Modules | ? ModuleName -match Slinky |
     %{ (Get-FileHash $_.FileName -Algorithm SHA256).Hash.Substring(0,16) } }
   ```
   和 `dist\SlinkyNative.dll` 的前 16 位一致才算生效。
4. 打开 GUI，`%TEMP%\slinky.log` 里应看到三行：
   ```
   frosted: 1920x1009 -> 480x252, blur r=3, mean=xx.x
   frosted: image N created (480x252)
   frosted: draw alpha=1.00 panel=1920x1009 image=N (480x252)
   ```
5. 屏幕验收：
   - 面板背后是世界画面的模糊版，不是纯色；转视角 1/4 秒内跟着变；
   - 顶部有一道细高光；
   - 关掉 GUI 后无残留、无闪烁（`g_active` 归零后不再读回）；
   - 帧率：开 GUI 掉不超过 3–4 fps。

### 如果还是不显示，按这两条二分（不用猜）

- **`frosted: image N created` 有、但屏幕没变化** → 说明 handle 路径通了、是画面内容问题：
  看 `mean=` 是不是 0（0 = 读回的是黑屏，世界不在默认 framebuffer 里，捕获点要换）；
  再把 `gui_draw_frosted` 里的 tint 临时删掉、底板也删掉，只留 `FillPaint + Fill`，确认到底是图没画还是被盖住。
- **压根没有 `frosted:` 日志** → 调用没进去：`SLINKY_FROSTED_GUI` 没开 / DLL 没换（比 SHA）/
  `ptr_to_gui_module_descriptor[0x14]` 一直是 0。

`include/slinky/gui_frosted.h` 第 9 行改回 `#define SLINKY_FROSTED_GUI 0`，重编 DLL + exe。
