# 交接：GUI 面板不够通透（不是模糊的问题，是可见面积的问题）

> 2026-11-14 · 给 Claude
> 前置：毛玻璃管线已经能跑，开关也有了（`frosted_gui`）。这一份只说**观感**：用户和评审都认为
> 「不够毛玻璃」「不够通透」。

---

## 0. 一句话

模糊本身没问题，问题在于**你能看见模糊的地方太少**。整个面板被卡片铺满，卡片不透明度 0.82，
背后世界只透 18%，毛玻璃只从卡片之间那 8–12 px 的缝里漏出来。

调模糊半径、调 tint、调降采样级别都**不会**解决这件事 —— 那些改的是「缝隙里那点东西有多糊」。

---

## 1. 现状数值

| 层 | 值 | 出处 |
|---|---|---|
| 全屏遮罩（面板底） | `gui_card_header_grey_level × 0.75` alpha | `gui_cards.cpp` `card_open_animation` |
| 毛玻璃图 | 1/4 降采样 + radius 5 两趟模糊 | `gui_frosted.cpp` |
| 毛玻璃 tint | `(0.055, 0.058, 0.070)` × **8%** | `gui_frosted.cpp` `gui_draw_frosted` |
| **卡片底色** | 灰 × **0.82** alpha | `gui_cards.cpp` `draw_module_cards` 的 `cc.w` |
| 卡片材质 | 顶白 6% → 底黑 18% 渐变 + 1px 白 7% 描边 + 顶部 44px 白 10%→0 柔光 | `gui_layout.cpp` `draw_rect_rounded` |

面板里一屏能放 18 个卡片（两列 × 9 行），卡片几乎盖满整个面板区域。

---

## 2. 为什么现在看着「实」

三个因素叠加：

1. **覆盖率**：卡片占面板可见面积的 ~90%，剩下 10% 是间隙和边缘。毛玻璃只在 10% 里可见。
2. **卡片不透明度 0.82**：即使在那 90% 里，世界也只能透出 18%，而且是**被卡片底色染过的 18%**。
3. **材质层**（渐变 + 描边 + 柔光）进一步把卡片「做厚」，视觉上更像一块板而不是一片玻璃。

对比：用户满意的那个截图是 **Profiles 页** —— 只有 9 个卡片 + 一个大按钮，下面一大片空面板，
所以背后世界看得见。Combat / Visual 页卡片塞满，就完全没有通透感了。

**结论：这是布局密度 × 卡片不透明度的问题，不是模糊参数的问题。**

---

## 3. 可动的旋钮（按影响从大到小）

### A. 卡片不透明度（影响最大，一行）

```c
// gui_cards.cpp, draw_module_cards
cc.w = gui_frosted_gui_on.value ? 0.82f : 1.0f;
//                                  ↑ 0.68 / 0.62 / 0.55
```

**参考**：macOS / iOS 的侧边栏玻璃通常 0.55–0.70 不透明度 —— 因为它们背后是**已经模糊**的画面，
没有高频噪声，所以文字仍然能读。这里的条件一样（背景已经是 1/4 降采样的模糊图）。

建议先给 **0.68**，如果文字还清楚就再往下试到 0.60。

### B. 材质层强度

```c
// gui_layout.cpp, draw_rect_rounded
V4e top    = nvg_rgba_f(1,1,1, 0.06f);   // → 0.03
V4e bottom = nvg_rgba_f(0,0,0, 0.18f);   // → 0.10
V4e lit    = nvg_rgba_f(1,1,1, 0.10f);   // 柔光 → 0.05
V4e edge   = nvg_rgba_f(1,1,1, 0.07f);   // 描边 → 0.04
```

卡片的「厚度感」大半来自这里。降一半之后卡片会轻很多，代价是「叠在一起的层次感」变弱 ——
卡片之间有 8px 间隙，靠描边区分，描边降到 0.04 以下就会糊成一片，**别再低**。

### C. 卡片底色本身

卡片底色是 `gui_card_background_grey_level`（rdata 常量，不便改）。
但可以**在绘制时乘一个系数**：

```c
volatile float ck = gui_card_background_grey_level;
ck *= 0.75f;                       // 更暗的底 + 更低的不透明度 = 更透，但文字对比反而更好
```

暗底的好处：白字的对比度靠「暗」而不是靠「厚」，所以可以更透而不牺牲可读性。

### D. 全屏遮罩

`card_open_animation` 里那层遮罩 `gui_card_header_grey_level × 0.75` 也压在世界上。它的 alpha 来自
rdata 常量 `colour_alpha_0_75`，改不了值，但可以**在毛玻璃开启时不画它**：

```c
if (!gui_frosted_gui_on.value) {
    // 原来的遮罩
}   // 开着毛玻璃时由 tint 代替，不要两层都压
```

这一刀很值：现在是「遮罩 75% + 卡片 82%」两层压着，实际透出来的是 `0.25 × 0.18 ≈ 4.5%`。

### E. 布局（最后一招，代价高）

- 卡片高度压一点（`row_height_20_in_gui_cards` 相关），让一屏放得下更多内容 → 反而不通透，**不建议**
- 或者两列改三列 → 卡片变窄，间隙总面积变大 → 通透感提升，但文字空间被压
- 或者卡片之间间隙从 8px 加到 12px → 缝变宽，但面板能放的内容变少

**E 属于设计取舍，要用户拍板，别自己改。**

---

## 4. 建议的推进顺序

```
第一步：D（去掉重复的遮罩层）        —— 一行 if，立刻多透一大截
第二步：A（卡片 0.82 → 0.68）        —— 一行
第三步：看效果，再决定要不要 B（材质降一半）
```

每步都是一行改动，**分开交付**，让用户能指着说「第一步对了、第二步过了」。

---

## 5. 约束

1. **模糊参数别动**。`CAP_DOWNSTEPS` / `gui_frosted_blur` / tint 都不是这次的问题所在。
   用户已经明确说过「不是模糊的问题」。
2. **卡片不透明度只在新样式分支里改**：`gui_frosted_gui_on.value ? 0.68f : 1.0f` ——
   关掉开关必须还是原来的 1.0，否则「关掉 = 原版」的承诺就破了。
3. **文字可读性是硬门槛**。判断标准：卡片里 14px 的白字压在同一位置，能一眼读出模块名。
   读不清就把 alpha 加回去 0.02–0.03，不要靠加深描边去救。
4. **别动布局**（卡片高度、列数、间隙）。那是设计取舍，不是视觉修复。

---

## 6. 验收

1. **Combat 页（18 个卡片）**：能看出背后世界的**大色块**（草地绿 / 石墙灰 / 天空），
   但看不出方块边缘。这是「通透」的定量标准。
2. **Profiles 页**：比现在更透，但不要到「文字浮在画面上」的程度。
3. **关掉 `frosted_gui`**：panel 恢复到实心灰底、卡片 1.0，和原版像素级一致。
4. **文字**：随便读三个模块名 + 它们的描述，不需要凑近。
5. **掉帧不变**：这些改动只涉及 alpha 和一次绘制分支，不该带来任何帧率变化 ——
   如果变了，说明有别的副作用，回去查。

---

## 7. 附：为什么「调模糊」没用

模糊半径从 3 到 5、降采样从 1/4 到 1/8，改的都是**那张模糊图本身有多糊**。
但用户看到的是「透过面板能看见多少世界」——

```
能看见的世界 = 可见面积（卡片间隙 + 边缘）× 卡片透光率 × 遮罩透光率
             ≈ 10% × 18% × 25% ≈ 0.45%
```

把模糊半径翻倍，这个 0.45% 一点不变。所以别在那条路上继续花时间。
