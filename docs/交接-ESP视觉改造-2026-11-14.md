# 交接：Player ESP / Name Tags 视觉改造（可开关，风格统一）

> 2026-11-14 · 给 Claude
> 目标：把这两个模块的**视觉**做出来，逻辑一行不动。允许自由发挥，但必须能被一个开关关回原样，
> 而且要和现在 GUI 的材质语言是一套东西。

---

## 0. 一句话

Player ESP 现在是一圈线框，Name Tags 是「文字 + 一块方底 + 一条血条」。
把这两个升级成有设计感的东西 —— **你来定具体怎么做**，但三条硬要求：**能开关**、**风格和 GUI 统一**、**不掉帧**。

---

## 1. 现状：它们怎么画的

两个模块都在**世界渲染阶段**（descriptor 的 `handlers[6]`，3D 事件），不是 NanoVG，是 OpenGL 固定管线。

### Player ESP（`src/logic/visual/player_esp.cpp`）

```c
extern "C" void player_esp_render_mode_1(Render3d *h);   // 3D 盒子（默认）
extern "C" void player_esp_render_mode_0(Render2d *h);   // 2D 屏幕盒子（mode = 0 时）
```

- 顶点表：`player_esp_box_corners_around_feet[8]` —— 一个单位立方体的 8 个角
- 画法：`glPushMatrix` → `glTranslatef`（到玩家）→ `glScalef`（到玩家尺寸）→ 逐条棱 `glBegin(GL_LINES)` 或填充
- 可用 GL：`glPushMatrix / PopMatrix / Translatef / Scalef / Rotatef / LineWidth / Color3f / Color4f / Enable`
- 现有设置（都在 descriptor 里，已接线）：
  `line_width` `mode`(0=2D,1=3D) `show_2d_box` `hurt_effect` `filled` `health_bar` `range`
  `target_colour` `friend_other_colour` `hide_friendlies` `override_target_color` `color_mode`

### Name Tags（`src/logic/visual/name_tags.cpp`）

```c
extern "C" void name_tags_render(RenderEvt *h);   // line 392
```

- 位置由 native 算，**文字本身是调 Java 的 `FontRenderer` 画的**（native 只负责算出屏幕坐标 + 颜色字符串）
- 背景板、血条这类「几何」是自己用 `glBegin(GL_QUADS)` + `glVertex2f` 画的
- 可用 GL：`PushMatrix / PopMatrix / Translatef / Scalef / Color3f / Color4f / Enable / Disable / BlendFunc / Begin / Vertex2f / End`
- 现有设置：`scale` `distance_scaling` `background` `text_shadow` `show_equipment` `enchantments`
  `range` `own_name_tag` `display_name` `show_health` `distance` `health_format`

## 2. 风格基准：现在的 GUI 是什么材质语言

改造后的视觉必须能跟下面这套放在一起不违和。三个特征，都从 GUI 的代码里来：

| 特征 | 具体值 | 出处 |
|---|---|---|
| **渐变**（顶亮底暗） | 顶部 `白 6%` → 底部 `黑 18%` | `gui_layout.cpp` 的 `draw_rect_rounded` |
| **细线** | 1px，`白 7%` 整圈描边 | 同上 |
| **柔光** | 顶部 44px 内 `白 10% → 0` | 同上（sheen 段） |
| **薄雾** | 冷灰 `(0.055, 0.058, 0.070)`，不透明度由设置给 | 毛玻璃的 tint |
| **不用纯黑/纯白** | 最亮的白只到 10–20%，最暗的黑只到 18% | 全 GUI |

一句话：**低对比、细线、渐变、半透明**。别用高饱和纯色，别用粗描边。

## 3. 视觉方向（给参考，不锁死）

### Player ESP

3D 线框能玩的东西不多，但这几种都是成熟做法，选一个或组合：

1. **角标框（corner brackets）** —— 不画完整 12 条棱，只画每根棱两端各 25%，看起来像「瞄准框」。
   最省顶点，视觉最干净。
2. **双色描边** —— 一条向外扩 0.01 的淡色线垫在下面（模拟外发光），主框用目标色。
   相当于给线框加了 GUI 那层 1px 描边。
3. **纵向渐变** —— `glBegin(GL_LINES)` 时逐顶点 `glColor4f`，顶角亮、底角暗，
   和卡片的「顶亮底暗」是同一个语言。
4. **地面投影** —— 脚下一个扁椭圆（`glBegin(GL_TRIANGLE_FAN)`），颜色取目标色 alpha 15%。
   廉价，但立刻有「落地感」。
5. **血条 / hurt 效果**沿用现有逻辑，只换配色和线宽。

### Name Tags

1. **底衬改成圆角药丸** —— 现在是方块。圆角可以用 `GL_TRIANGLE_FAN` 画（4 段圆弧 × 4 角），
   或者简化的「两端半圆 + 中间矩形」。底色用 GUI 那套冷灰 + 不透明度，别用纯黑。
2. **血条重做** —— 2px 高、圆头、绿→黄→红三段渐变，放在名字下方，长度跟血量走。
3. **层级** —— 名字 100%，数值（血量/距离）70% 不透明度、小一号；装备那一行 60%。
   现在它们是一个亮度，读起来是一坨。
4. **文字阴影**已有开关（`text_shadow`），新样式下建议默认开，偏移 1px、黑 45%。

**共同要求**：目标玩家（current target）和普通玩家要有**明显的层级差**，但差别靠「亮度/线宽/透明度」，
不要靠「红 vs 蓝」这种撞色。

## 4. 开关：必须能一键关回原样

参考毛玻璃那一套（`include/slinky/gui_frosted.h` 的 `FrostBool` + `gui_frosted_gui_on`），
两个模块各自带一个开关，互不影响。

### 4.1 在自己文件里定义（模板）

```c
// 模块自己的视觉开关，布局和引擎 visitor 一致（同 bed_esp.cpp / gui_frosted.cpp）
struct StyleBool {
    char pad[0x10];
    const char *label;              // +0x10
    unsigned char value, saved;     // +0x18 / +0x19
    char pad_1a[6];
};
extern "C" const char str_style_on_player_esp[] = "new_style";
StyleBool player_esp_style_on = { {}, str_style_on_player_esp, 1, 1, {} };
```

### 4.2 挂到设置页

模块的设置页在 `src/logic/visual/player_esp.h` / `name_tags.h` 里（CMake 把 `src/logic/**/*.h` 当 `.cpp` 单独编译，
所以直接改 header 就生效）：

```c
// gui 回调里
W_bool(window, gui, &player_esp_style_on);
// register 回调里（存档 key，不写这个重开游戏就丢）
R_bool(module, str_style_on_player_esp, &player_esp_style_on);
```

### 4.3 绘制里分支

```c
extern "C" void player_esp_render_mode_1(Render3d *h) {
    if (player_esp_style_on.value) { /* 新视觉 */ }
    else                          { /* 原来的代码，一个字都不改 */ }
}
```

**硬要求**：关掉时必须和现在**像素级一致**。做法就是把现有绘制代码原样放进 `else` 分支，
不要「顺手优化」它。

## 5. 约束

1. **只动绘制**。目标筛选、距离、可见性、hurt 判定、健康值计算，全部不动。
2. **GL 状态必须成对**：`glPushMatrix` / `glPopMatrix`、`glEnable` / `glDisable`、
   `glBegin` / `glEnd`。这个仓库里 3D 事件之后 HUD 和 GUI 还要用同一套状态，
   漏一个 `Pop` 就会让后面的绘制全体错位（踩过）。
3. **不要在 3D 阶段开深度测试以外的东西**：深度测试按需开关并还原，别碰 scissor、别碰 blend mode 之外的状态。
4. **不做后处理**：不要 framebuffer、不要 shader、不要读回。这个客户端的 3D 路径没有后处理管线，
   加一层就是掉帧。
5. **顶点数要克制**：目标是最多 30 个玩家同屏。角标框每个玩家约 48 个顶点，可接受；
   如果要画圆角药丸，圆角段数控制在 4–6 段/角。
6. **别动 `line_width` 的语义**：它已经在设置里，用户会调；新样式的粗细跟着它走。

---

## 6. 验收

1. **开关关掉 → 和现在完全一样**。截图对比，像素级。
2. **开关打开 → 一屏里 10 个玩家**：目标玩家一眼能挑出来，普通玩家读得清，不刺眼。
3. **和其他界面同一套语言**：把 GUI 和毛玻璃打开放一起截图，颜色/线宽/透明度在同一个体系里。
4. **不掉帧**：3D 阶段多画的顶点不超过原来的 2 倍。
5. **存档**：改设置 → 关游戏 → 重开，开关状态还在（profile 里能看到 `new_style`）。
6. **GL 状态不漏**：开关来回切几次，HUD/毛玻璃/卡片都正常，没有整屏错位或残留。

---

## 7. 这条路上踩过的坑

| 坑 | 症状 |
|---|---|
| `glPushMatrix` / `PopMatrix` 不成对 | 后面所有绘制整体偏移、缩放错乱，而且很难定位 |
| 深度测试忘了还原 | 后面的 HUD 全部被方块挡住 |
| 逐顶点 `glColor4f` 但没开 blend | 渐变变成实色，或者整段透明不可见 |
| 在 3D 阶段用了 NanoVG 的坐标 | 完全不在一个空间，画出来是乱的 |
| 圆角用太多顶点 | 10 个玩家 × 每个 4 角 × 8 段，一帧上千顶点，帧数掉 |
| 改了现有绘制的顺序 | hurt 效果和 filled 的组合依赖顺序，换了会闪 |
